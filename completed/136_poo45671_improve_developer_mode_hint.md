# 136 poo45671: Improve developer mode connection hint for non-qemu machines

Ticket: https://progress.opensuse.org/issues/45671
Branch: feature/405_poo45671_improve_developer_mode_hint

## Problem

The developer mode web UI always shows the QEMU-style VNC hint (e.g.
"VNC port: 109"). For non-qemu backends (e.g. hyperv/xen via Xvnc) the real
VNC endpoint differs (e.g. openqaw5-xen-1.qa.<internal>:5903) and is only known
on the worker/backend side. The hint must therefore come from the worker
configuration, not be hardcoded in the web UI.

## Architecture (architect output)

Add a worker property `DEVELOPER_CONNECTION_HINT` (per worker instance,
e.g. via `workers.ini` generated by salt). When set, its text is sent over
the WebSocket `connecting` message and displayed instead of the default
QEMU VNC hint. Unset means existing behaviour, so no regression for qemu.

Relevant files:

- `lib/OpenQA/Schema/Result/Workers.pm` (~350): worker property accessor
- `lib/OpenQA/Shared/Plugin/SharedHelpers.pm` (~42): connection params
- `lib/OpenQA/LiveHandler/Controller/LiveViewHandler.pm` (~474): WS payload
- `assets/javascripts/running.js` (~1225): WS message handling
- `templates/webapi/test/live.html.ep` (~48): developer mode notice

## Implementation steps

1. Model: `developer_connection_hint` accessor in `Workers.pm` reading
   `DEVELOPER_CONNECTION_HINT`.
2. Controller: `SharedHelpers` returns a hashref
   `{vnc_arg => ..., developer_connection_hint => ...}`.
3. LiveViewHandler: pass the hashref as `$data` to `connect_to_cmd_srv`.
4. JS: `running.js` stores `developerConnectionHint` and writes it as plain
   text (`textContent`, no HTML) into `.developer-connection-hint-text`.
5. Template: split `#developer-vnc-notice` into default block and custom
   block, toggled via `data-visible-on` / `data-hidden-on`.
